# Release Workflow

1. **Planning** confirms release scope, supported platforms, prerequisites, and rollback expectations.
2. **Review** checks the release diff and known risks.
3. **Testing** reports required suite/build/device evidence and unresolved failures.
4. **Security** reviews release-sensitive changes, permissions, and secret handling.
5. **Documentation** prepares accurate release notes and migration guidance.
6. **DevOps** checks reproducible build/release configuration and recovery steps.
7. **Orchestrator** provides a go/no-go evidence summary to the developer.

Release, publishing, signing, deployment, and external announcements require explicit authorization.
